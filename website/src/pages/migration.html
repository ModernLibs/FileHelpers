1. Package and namespace

This is the change every project needs.

- using FileHelpers; - using FileHelpers.Events; - using FileHelpers.MasterDetail; + using ModernLibs.FileHelpers; + using ModernLibs.FileHelpers.Converters; // only if you write custom converters

The library targets .NET 10 and needs C# 11 or later. Record types are checked at compile time: a layout mistake that 3.x reported at run time is now a build error or warning (diagnostics).

2. What is not included

Anything that creates or changes a record layout at run time conflicts with source generation and Native AOT. A second group was left out because other tools do it better.

4. What behaves differently

Code that compiles but does something else. Since 4.8.0 the list is short: quoting, trimming, comment lines, empty fields and conversion errors all follow 3.x.

Default encoding is UTF-8

3.x used the system code page on .NET Framework. If your files use a legacy code page, set it:

Encoding.RegisterProvider(CodePagesEncodingProvider.Instance); var engine = new FileHelperEngine(Encoding.GetEncoding(1252));

Lines end with \r\n everywhere

3.x used Environment.NewLine, which is \n on Linux and macOS. Set engine.NewLineForWrite = "\n"; if you need that.

HeaderText and FooterText can be null

They are null when there is no header or footer; in 3.x they were empty strings.

Which members are mapped

3.x mapped every instance field of any accessibility. Here public, internal and protected internal fields and properties are mapped. A private field that 3.x would read as a column is reported (MLFH028), so a migrated record cannot lose a column silently.

[DelimitedRecord(",")] public sealed class Invoice { public int Number; internal decimal Total; // mapped, as in 3.x [FieldHidden] internal string? Note; // left out of the layout private int _retries; // MLFH028: a column in 3.x, not mapped here }

Multi-record files ignore [IgnoreFirst]

MultiRecordEngine does not apply [IgnoreFirst] / [IgnoreLast]. Header lines are still dropped as long as no selector matches them.

5. What is new

  • Source generation and AOT. No reflection at run time; works with PublishAot=true and trimming.
  • Structs and records. struct, record struct, positional records, required members.
  • More field types. DateOnly, TimeOnly, DateTimeOffset, TimeSpan and enums without a custom converter.
  • Streaming. ReadSync, ReadAsync, callbacks, and async multi-record and master/detail engines.
  • Parallel reads with sequential semantics.
  • StopReading in the before-read event, and ISpanConverter<T> for allocation-free converters.
  • Error details. ErrorInfo.FieldName, ColumnIndex and RawFieldValue.

6. Troubleshooting

InvalidOperationException: No IRecordDescriptor<T> registered
The record type was not processed by the generator. Check that it has [DelimitedRecord] or [FixedLengthRecord], that the build shows no MLFH errors for it, and that the project references the package.
Columns are shifted, or a field you did not expect is read
An internal member is mapped, as in 3.x. Mark members that are not in the file [FieldHidden].
MLFH026 on every record type
The project compiles with a C# version below 11. Remove the <LangVersion> setting or set it to 11 or later.
MLFH013 unsupported field type
The field type has no built-in conversion. Add a custom converter.
InvalidOperationException from FileHelperAsyncEngine<T>
One engine instance runs one read or write session at a time. Call Close() first, or use a separate instance.
