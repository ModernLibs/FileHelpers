How it works

The source generator checks every record type when you build. Many mistakes that FileHelpers 3.x reported at run time with a BadUsageException are build errors here. The rules are reported by an analyzer in the same assembly as the generator, so they appear as you type and point at the offending declaration.

[FixedLengthRecord] public sealed class Employee { [FieldFixedLength(6)] public int Id; public string Name = ""; // error MLFH002: missing [FieldFixedLength] }

When a record has an error, the generator does not emit its descriptor. Other record types in the same project are not affected.

Suppressing diagnostics

Warnings (MLFH007, MLFH008, MLFH009, MLFH028, MLFH029) and MLFH001 can be suppressed as usual: #pragma warning disable, [SuppressMessage], an .editorconfig severity or <NoWarn>.

Every other error means the record has no working descriptor. These are not configurable: #pragma, .editorconfig and <NoWarn> do not hide them, and the build fails until the record is fixed.

Two paths can still hide them, and neither fails silently. With [SuppressMessage] or <RunAnalyzers>false</RunAnalyzers>, the generator registers a descriptor whose members throw a BadUsageException naming the record and each error. Creating or using an engine for that record throws it.

Records from other source generators

The FileHelpers generator cannot see types that another source generator adds to the compilation, so such a record gets no descriptor and no diagnostic; using it throws InvalidOperationException (No IRecordDescriptor<T> registered). Declare record types, and all their mapped members, in your own source files.

If you used FileHelpers.Analyzer

The 3.x analyzer was a separate package that suggested style fixes: use the generic engine, prefer [FieldHidden], avoid obsolete names. Most of its advice is now simply how the API works: only the generic engines exist, and [FieldIgnored] was removed in favour of [FieldHidden]. You do not need to install anything; remove the FileHelpers.Analyzer reference when you migrate.
