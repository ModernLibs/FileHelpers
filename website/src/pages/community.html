Credits

The API and behaviour of this library are modelled on FileHelpers, created by Marcos Meli and maintained with the help of many contributors. Attribute names, engines, events, error modes and exception types are theirs; FileHelpers 3.x is the reference for how this library behaves. Thank you to everyone who built and maintained it.

The original project's own credits page lists the people behind it.

This is not the original project. ModernLibs.FileHelpers is an independent reimplementation. Please report problems with this library in its own issue tracker, not upstream.

A good bug report

Include a minimal record type, a few input lines, what you expected and what happened. If the behaviour differs from FileHelpers 3.x, say so: 3.x is the reference, and the migration guide lists the known differences.

Contributing

Bug reports, documentation fixes and pull requests are welcome. For a feature, open an issue first so the API can be agreed before you write code.

Build and test

You need the .NET 10 SDK version pinned in global.json.

dotnet build -c Release # main suite (TUnit) dotnet test --project tests/ModernLibs.FileHelpers.Tests -c Release # the migration sample must keep working dotnet run --project samples/MigrationSamples -c Release

Design constraints

These are requirements, not preferences. Pull requests that break them cannot be merged.

  1. .NET 10 onlyThe library targets net10.0; there is no multi-targeting.
  2. AOT and trimming safeNo reflection, Reflection.Emit, Expression compilation or MakeGenericType. Everything that depends on the record type is generated at compile time.
  3. Allocation budgetReading a value-type struct record must not allocate per record or per line on the callback and streaming paths. Tests enforce it.
  4. FileHelpers 3.x compatibilityNames, signatures, exceptions and error handling follow 3.x. Intentional differences are documented in the migration guide.

The full contributing guide covers the repository layout, mutation testing, fuzzing and benchmarks.

Where help is wanted

The gap analysis lists 3.x features that could be added without reflection and are still open, such as [FieldArrayLength], header lines from [FieldCaption] and engine-level overrides for record options.
