Important

Layouts are fixed at compile time

A source generator turns each record type into parsing code when you build. That is why the library is fast and works under Native AOT, and it is also why anything that creates or changes a layout at run time is not available: ClassBuilder, engine.Options, the non-generic engines and SmartFormatDetector. Declare one record type per layout.

Databases and Excel are out of scope

FileHelpers 3.x could link files to SQL Server, Access and Excel through DataLink and the storage classes. Those are not included. Read or write the typed records here and use your data-access or spreadsheet library for the other side.

Defaults differ from 3.x in two places

The default encoding is UTF-8 on every platform, and written lines end with \r\n on every platform. Both can be set on the engine (Encoding, NewLineForWrite). The migration guide has the details.

FAQ

My file has a header line. How do I ignore it?
Put [IgnoreFirst(1)] on the record class. For footer lines use [IgnoreLast(n)]. The skipped text is available afterwards as engine.HeaderText and engine.FooterText.
I want to write a file with a header.
Set engine.HeaderText before you call WriteFile. It is not generated from the field names (GetFileHeader() from 3.x is not available). engine.HeaderText = "Id,Name,Balance,Joined"; engine.WriteFile("customers.csv", customers);
Some characters are not read correctly.
That is an encoding problem. The default is UTF-8; pass another encoding to the engine. Encoding.RegisterProvider(CodePagesEncodingProvider.Instance); // needed on .NET for code pages var engine = new FileHelperEngine(Encoding.GetEncoding(1252));
How can I skip certain lines when reading?
For fixed rules use attributes on the record: [IgnoreEmptyLines], [IgnoreCommentedLines('#')] or [ConditionalRecord(RecordCondition.ExcludeIfBegins, "//")]. For anything else, handle the BeforeReadRecord event or implement INotifyRead<T> and set e.SkipThisRecord = true.
My DateTime field has a different format.
Say so on the field: [FieldConverter(ConverterKind.Date, "M-d-yyyy")]. Without a format, DateTime fields use ddMMyyyy, as in 3.x. See converters.
A numeric field is sometimes empty.
Declare it nullable (int?) or give it a default with [FieldNullValue(0)]. Otherwise an empty value raises NullValueNotFoundException. Example.
The build says MLFH-something.
Record layouts are checked when you build. The message names the field; the diagnostics reference explains each rule and its fix.

[ConditionalRecord(condition, text)]Include or exclude lines that begin with, end with, contain or match a regex.

Members that are public, internal or protected internal are mapped, fields and properties alike. private and protected members cannot be mapped; the build tells you when that would drop a column (MLFH023, MLFH028).

Converters

Most field types need no attribute: string, char, bool, all integer types, decimal, double, float, DateTime, DateOnly, TimeOnly, DateTimeOffset, TimeSpan, Guid, enums and their nullable forms. Add [FieldConverter] to change the format.

You wantWrite
A date format[FieldConverter(ConverterKind.Date, "yyyy-MM-dd")]
Several accepted date formats[FieldConverter(ConverterKind.DateMultiFormat, "yyyy-MM-dd", "dd/MM/yyyy")]
A decimal comma[FieldConverter(ConverterKind.Decimal, ",")]
A culture for one field[FieldConverter(ConverterKind.Decimal, CultureName = "de-DE")]
Other boolean texts[FieldConverter(ConverterKind.Boolean, "yes", "no")]
Your own rules[FieldConverter(typeof(MyConverter))], see the example

Defaults follow FileHelpers 3.x and do not depend on the machine's culture. bool accepts true/false, 1/0, y/n and t/f. Enums are read by name, ignoring case.

Performance

Do not load what you can stream

ReadFile builds an array of every record. For large files, use ReadAsync, ReadSync, a callback or FileHelperAsyncEngine<T>: one record is in memory at a time.

Discard fields you do not use

Mark columns you never read with [FieldValueDiscarded]. The column still counts in the layout, but its value is not converted or stored.

Use structs for numeric data New in 4.x

A struct or record struct whose fields are all value types is read through a callback or ReadSync without any heap allocation per record. Example.

Choosing a read method

All of them go through the same record pipeline, so they produce the same records, errors and line numbers for the same input. The opt-in features document describes each one.

Debugging

Read the whole exception

Exceptions carry the context you need. ConvertException has LineNumber, ColumnNumber, FieldName, FieldType and FieldStringValue.

try { engine.ReadFile("customers.csv"); } catch (ConvertException ex) { Console.WriteLine($"Line {ex.LineNumber}, field {ex.FieldName}: '{ex.FieldStringValue}' is not a {ex.FieldType.Name}"); }

Collect errors instead of stopping

With ErrorMode.SaveAndContinue the good records are returned and the bad ones are listed in engine.ErrorManager.Errors. Example.

Let the build find layout mistakes

Do not suppress MLFH errors. A hidden error comes back at run time as a BadUsageException that names it. See suppressing diagnostics.
