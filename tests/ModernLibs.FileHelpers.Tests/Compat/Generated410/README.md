# Generated410: descriptors made by the 4.10.0 generator

The 20 `*.g.cs` files in this folder are the output of the **4.10.0** source generator for the record shapes of
`../Compat49Twins.cs`: the 19 shapes of `Generated49` and the path-only shape `Compat49NotEmpty` (`[FieldNotEmpty]`
on a quoted and on a plain field). They are checked in so that 4.10.1 and later runtimes are tested with descriptors
compiled against 4.10.0, as a consumer library built against 4.10.0 would carry. `GeneratedCodeContractTests` and
`docs/GENERATED-CODE-CONTRACT.md` list the library members that these files bind to, the members added in 4.10 included
(`ITokenizedDescriptor<T>`, `RecordTokens`, the `RecordParsing` read helpers, `IRecordWriterDescriptor<T>`,
`RecordWriter` with `Quote`, `WriteQuoted`, `Pad` and `WritePadded`, `RecordFormatting.Format<T>`).

`Compat410Tests` runs them on the current runtime:

- Each shape reads and writes back every input of `Compat49Inputs` with the text that `Golden49/<Shape>.txt` holds. 4.10
  keeps the 4.9.1 behaviour of generated code, so the 4.9.1 golden files are the reference; there is no `Golden410`.
- The default read path (the tokenized one for an eligible shape), the scalar tokenizer and the forced legacy path read
  every input alike, and the record writer and the legacy writer write alike (the checks of `Compat49Tests` on the
  checked-in descriptors).
- The snapshot has all 20 shapes, every descriptor implements `IRecordWriterDescriptor<T>`, and the plain, the quoted
  and the `[FieldNotEmpty]` shape are read through `ITokenizedDescriptor<T>`.

The record types are the plain `Compat410X` types of `../Compat410Records.cs`: the members of `Compat49XTwin`, no
record attributes, so the current generator makes no second descriptor. The inputs, the write cases and the golden
texts are those of the shape `Compat49X` (`Compat49Matrix.ShapeName` maps the name). The custom converters of
`Compat49Twins.cs` are shared.

**Do not regenerate the `*.g.cs` files with a newer generator.** They must stay 4.10.0 output. When a `Compat410Tests`
case fails against `Golden49`, the runtime changed what a 4.10.0 consumer sees: fix the runtime, not the snapshot. When
the generator changes what it emits, the current descriptors (the twins) change and `Generated410` does not.

## How the files were made

1. The generator is the one of this repository at commit `6739f20` (branch `task/T50-docs`); its output is equal at
   `20a6e7d`. If a commit changes `src/ModernLibs.FileHelpers.Generator` (other than the `Version` line) before the
   `v4.10.0` tag, the files are no longer 4.10.0 output and must be made again (check: `git diff 6739f20..<tag commit>
   -- src/ModernLibs.FileHelpers.Generator` shows the `Version` line only). Its `[GeneratedCode]` version string is
   the build `Version`, which was still `4.9.1` in the project files, so the build ran with `-p:Version=4.10.0`; the
   files say `4.10.0`, as the generator of the release does. Build in WSL, SDK 11.0.100 (`global.json`):

   ```bash
   dotnet build tests/ModernLibs.FileHelpers.Tests -c Release -f net10.0 -p:Version=4.10.0 \
     -p:EmitCompilerGeneratedFiles=true -p:CompilerGeneratedFilesOutputPath=$HOME/scratch/t50-gen \
     --no-incremental -p:UseSharedCompilation=false
   ```

   `0 Warning(s)`, `0 Error(s)`. The generator ran on the `Compat49...Twin` types of the test project, which carry the
   attributes, and wrote one `ModernLibs.FileHelpers.Tests.Compat.Compat49<Shape>Twin.<hash>.<Kind>.g.cs` for each, 20
   in all (the output folder is outside the repository).

2. Copy: for each of the 20 files:
   - the file is named `Compat410<Shape>.<Kind>.g.cs`;
   - the first line (`// <auto-generated/>`, with a UTF-8 byte order mark) is replaced by the same line without the mark
     and a header of five lines (origin, rename, `#pragma warning disable MLFH001`), as in `Generated49`;
   - every `Compat49<Shape>Twin` becomes `Compat410<Shape>` (`sed -E 's/Compat49([A-Za-z0-9]+)Twin/Compat410\1/g'`).

   Nothing else changed: each file, without its header, is equal to the generator output after the rename.
