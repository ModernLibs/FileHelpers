# Benchmark results: ModernLibs.FileHelpers 4.8.1 against 4.8.0

Recorded on 2026-11-08 as an A/B run: the same benchmark suites, built from two clones of the repository
on the same machine, one directly after the other.

| | Commit | Run |
|---|---|---|
| 4.8.0 | `9f67f29` (`main`) | 17:06 to 17:25 |
| 4.8.1 | `6b07324` (`release/4.8.1`) | 17:25 to 17:43 |

Only the suites that 4.8.1 changes were run: the read entry points of `FileHelperEngine<T>`
(`OptimizedParseBenchmarks`), the delimited comparison with FileHelpers 3.5.2
(`DelimitedComparisonBenchmarks`) and the writes (`WriteBenchmarks`). For the other suites and the
comparison with Sep, Sylvan and CsvHelper, see [v4.8.0.md](v4.8.0.md).

## Command

Run in each clone:

```bash
dotnet run -c Release --project benchmarks/ModernLibs.FileHelpers.Benchmarks -- \
  --filter "*OptimizedParseBenchmarks*" "*DelimitedComparisonBenchmarks*" "*WriteBenchmarks*" \
  --memory --exporters github --artifacts BenchmarkDotNet.Artifacts/ab
```

## Reading the results

The FileHelpers 3.5.2 and CsvHelper rows are controls: their code is the same in both runs. They moved
by between 6 % faster and 2 % slower, so treat a difference of that size as noise. The 4.8.1 read
gains are well above it.

## Summary

- **Reads are 8 to 26 % faster.** Records without quoted fields check their field count by counting
  delimiters instead of scanning the record. The file reads also use 16 KB buffers (the framework
  default was 4 KB) and `ReadFileAsync` opens the file for asynchronous I/O. At 100K rows:
  `ReadString` with a callback takes 77 ms instead of 92 ms, `ReadFile` with a callback 81 ms instead
  of 98 ms, and `ReadFileAsync` 90 ms instead of 114 ms.
- **`WriteFile` is 12 to 18 % faster** with a 16 KB write buffer: 637 ms instead of 758 ms for 1M rows.
  Each `WriteFile` call now allocates about 85 KB instead of about 10 KB, once per call and not per
  record. Every buffer stays below the 85,000-byte large object heap threshold.
- **`WriteString` is unchanged** (within noise).
- **Allocation per record is unchanged** on every read.
