# Benchmark results: early development snapshot (labelled v4.0.0)

> **Historical, not current.** These numbers were recorded during development, before the 4.3.0
> milestone (committed 2026-05-10), and were labelled "v4.0.0" at the time. The exact commit was not
> recorded. Since then the read pipeline, the converters and the source generator have been rewritten
> (4.8.0), so the numbers do not describe the current code. `SliceAllFields_SpanSlicer` measures
> `FixedLengthSlicer`, which is now internal. Only the fixed-width table has numbers; the other
> sections only describe how to run the benchmarks. See [BENCHMARKS.md](../../BENCHMARKS.md).
>
> **Not comparable with later results.** Before 4.8.0 a failed conversion silently became `default`,
> and the benchmark records did not match their data: delimited records read the header line as a
> record and could not parse the generated dates, quoted fields were not unquoted, and the
> "FileHelpers 3.x" record types resolved to ModernLibs.FileHelpers itself, so the 3.x comparison
> measured 4.x against 4.x. The fixed-width data used here contains only text fields and was read
> correctly, but the library has changed since. For current numbers see
> [v4.8.0.md](v4.8.0.md).

## Fixed-Width Parse Benchmarks

| Method | Rows | Mean | Gen0 | Gen1 | Gen2 | Allocated |
|--------|------|------|------|------|------|-----------|
| **ReadAllRows_Class** | 10K | 3.27 ms | 969 | 945 | 500 | 9.24 MB |
| ReadAllRows_Struct | 10K | 3.84 ms | 996 | 992 | 633 | 9.47 MB |
| **SliceAllFields_SpanSlicer** | 10K | **1.61 ms** | 498 | 498 | 498 | 4.95 MB |
| **ReadAllRows_Class** | 100K | 69.13 ms | 6250 | 6000 | 1750 | 91.73 MB |
| ReadAllRows_Struct | 100K | 60.92 ms | 5889 | 5778 | 1889 | 94.02 MB |
| **SliceAllFields_SpanSlicer** | 100K | **19.46 ms** | 3063 | 2969 | 1000 | 49.3 MB |

### Key Findings

- **SpanSlicer** is ~2x faster than full engine parse for raw field extraction (0.49x ratio at 10K, 0.28x at 100K)
- **Struct records** are slightly slower at 10K (1.17x) but faster at 100K (0.88x) — JIT warmup effect
- **Allocation** is similar between class and struct paths (1.02x ratio) — string field allocation dominates
- **Gen2 collections** are present for all paths — expected for large allocations

## Delimited Parse Benchmarks

Benchmarks compare ModernLibs.FileHelpers vs Sylvan.Data.Csv vs CsvHelper across:
- Full file read (all rows, all columns)
- Single column extraction
- Dataset sizes: 10K, 100K, 1M rows (PackageAssets: 25 columns)

Run locally to generate results:
```bash
dotnet run -c Release --project benchmarks/ModernLibs.FileHelpers.Benchmarks -- --filter '*DelimitedParseBenchmarks*'
```
