# Generated49: descriptors made by the 4.9.1 generator

The 19 `*.g.cs` files in this folder are the output of the **4.9.1** source generator (tag `v4.9.1`,
commit `3a045e0`). They are checked in so that the tests run descriptors compiled against 4.9.1 on the
current runtime, as a consumer library built against 4.9.1 would. `Compat49Tests` compares each one with
the descriptor that the current generator makes for the same record. `GeneratedCodeContractTests` and
`docs/GENERATED-CODE-CONTRACT.md` list the library members that these files bind to.

**Do not regenerate these files with a newer generator.** They must stay 4.9.1 output. If the runtime
changes and a `Compat49Tests` case fails, the runtime broke a 4.9.1 consumer: fix the runtime, not the
snapshot.

## How the files were made

1. Clone at the tag, outside the repository:

   ```bash
   mkdir -p ~/scratch/fh-49-gen && cd ~/scratch/fh-49-gen
   git clone ~/modernlibs/FileHelpers-release . && git checkout v4.9.1
   ```

2. SDK: `v4.9.1` has `global.json` with SDK `10.0.105` and `rollForward: latestPatch`. The clone was built
   with SDK **10.0.114** from `/usr/lib/dotnet` (`export PATH=/usr/lib/dotnet:$PATH DOTNET_ROOT=/usr/lib/dotnet`),
   which satisfies that `global.json`. `global.json` was not changed.

3. A throw-away project `~/scratch/fh-49-gen/compat49-probe/Compat49Probe.csproj` (`net10.0`, `Nullable` and
   `ImplicitUsings` on, an empty `Directory.Build.props` so the clone's analyzer settings do not apply):

   ```xml
   <EmitCompilerGeneratedFiles>true</EmitCompilerGeneratedFiles>
   <CompilerGeneratedFilesOutputPath>$(MSBuildProjectDirectory)/generated</CompilerGeneratedFilesOutputPath>
   ...
   <ProjectReference Include="../src/ModernLibs.FileHelpers/ModernLibs.FileHelpers.csproj" />
   <ProjectReference Include="../src/ModernLibs.FileHelpers.Generator/ModernLibs.FileHelpers.Generator.csproj"
                     OutputItemType="Analyzer" ReferenceOutputAssembly="false" />
   ```

   Its only source file is a copy of `../Compat49Twins.cs` (the 19 record types with their attributes, and
   the custom converters), with one change: `protected internal override bool CustomNullHandling` in
   `Compat49HexConverter` became `protected override`. The test assembly sees the library's internals
   (`InternalsVisibleTo`) and must keep `protected internal`; the scratch project does not see them. The
   modifier is not part of any generated file. `dotnet build -c Release` ended with 0 warnings and 0 errors,
   and every record got a working descriptor (no `InvalidRecordEmitter` output).

4. Copy: for each generated `ModernLibs.FileHelpers.Tests.Compat.Compat49<Shape>Twin.<hash>.<Kind>.g.cs`:
   - the file is named `Compat49<Shape>.<Kind>.g.cs`;
   - the first line (`// <auto-generated/>`, with a UTF-8 byte order mark) is replaced by the same line
     without the mark and a header of five lines (origin, rename, `#pragma warning disable MLFH001`), as in
     `Generated48`;
   - every `Compat49<Shape>Twin` becomes `Compat49<Shape>` (`sed -E 's/Compat49([A-Za-z0-9]+)Twin/Compat49\1/g'`).
     The renamed types are the attribute-free twins in `../Compat49Records.cs`, so the current generator makes
     no second descriptor for them.

   Nothing else changed: each file, without its header, is equal to the generator output after the rename
   (checked with `diff`). Running the steps again produced the same 19 files.

Record shapes: see `../Compat49Twins.cs` (one summary per type) and `../Compat49Inputs.cs` (the inputs).
